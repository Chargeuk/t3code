# Agents and Routines

## Overview

Implement reusable, file-defined **Agents** and **Routines** (the user-facing name for CodeInfo2 commands) as native T3 capabilities. Agent files define reusable profiles/templates (instructions, defaults, and Routines) applied to ordinary native T3 threads and delegated tasks; one profile can instantiate multiple threads. Native provider instances, ModelSelection, configuration/secrets, workspace/projects, task/thread/run identities, execution, cancellation, history, toolkits/RPC, Scheduler, and UI remain owned by their existing T3 authorities. Profiles do not own a parallel identity, provider, or conversation runtime, and do not replace native Skills or slash-command discovery. Adapt CodeInfo2 behavior at the boundary to T3's existing provider, orchestration, persistence, contracts, RPC/MCP, and UI. Definition files remain authoritative for profile content; T3 thread/run history and the minimum additional execution state belong in the existing SQLite/event-sourced lifecycle.

This plan owns native file-backed Agent and Routine definitions, named-Agent and Routine execution through existing T3 provider/thread services, their UI and applicable settings, and the shared Linux product runtime with explicit project Docker operations. [Repository Knowledge](0000001-repository-knowledge.md) owns ingestion/retrieval; [Codebase Questions](0000003-codebase-questions.md) owns the research parent and question service; [Pipelines](0000004-pipelines.md) consumes the shared Agent/Routine services and owns Pipeline execution. Research below was checked against T3 `39c72e0b65` and sibling CodeInfo2 `c90c52559`; product source matches the audited T3 baseline `39c72e0b65`. Links are evidence/navigation, not instructions to edit every file. Keep KISS across all sections, coordination waves, and proof: reuse existing paths and add no abstraction, gate, or framework without a verified gap and accepted requirement.
