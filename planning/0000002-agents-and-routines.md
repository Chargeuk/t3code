# Agents and Routines

## Overview

Implement reusable, file-defined **Agents** and **Routines** (the user-facing name for CodeInfo2 commands) as native T3 capabilities. Adapt CodeInfo2 behavior at the boundary to T3's existing provider, orchestration, persistence, contracts, RPC/MCP, and UI. Definition files remain authoritative; T3 thread/run history and the minimum additional execution state belong in the existing SQLite/event-sourced lifecycle.

This plan owns native file-backed Agent and Routine definitions, named-Agent and Routine execution through existing T3 provider/thread services, their UI and applicable settings, and the shared Linux product runtime with explicit project Docker operations. [Repository Knowledge](0000001-repository-knowledge.md) owns ingestion/retrieval; [Codebase Questions](0000003-codebase-questions.md) owns the research parent and question service; [Pipelines](0000004-pipelines.md) consumes the shared Agent/Routine services and owns Pipeline execution. Research below was checked against T3 `f69ad79ad9` and sibling CodeInfo2 `c90c52559`; links are evidence/navigation, not instructions to edit every file.

Ownership is explicit: this plan owns native Agent definitions/profiles, named-Agent execution through the existing thread/provider lifecycle, the shared ordered Routine service, core Agent/Routine UI and applicable settings, and the Linux product T3 runtime/project Docker control. [Repository Knowledge](0000001-repository-knowledge.md) owns canonical source IDs/paths, indexing/embedding state and settings, source lifecycle, and retrieval; this plan calls its service only for Routine re-ingestion. [Codebase Questions](0000003-codebase-questions.md) owns the research parent protocol, scoped question service/chat/MCP, and question UI; it consumes Knowledge and named Agent execution. [Pipelines](0000004-pipelines.md) owns file-backed native pipeline definitions, step executor/lifecycle/history/UI; it consumes this plan's same Agent and Routine services, calls Knowledge only for re-ingest and Questions only when invoked. Coordinate shared contracts/RPC, server layer composition, migration registration, client-runtime state/navigation/settings, and Compose edits so each shared file has one writer.

Do not treat recommendations in the older `t3code-port-research-2026-11-08.md` report as accepted requirements; use current CodeInfo2 source/definitions and callers together with current T3 seams. For same-host CodeInfo2 work, keep CodeInfo2 agents, flows, and plan helpers on the host; run T3 `vp`, `node`, and `cargo` through `npm run container:exec -- <command>` from the T3 root, using existing `container:up`/`container:dev` as needed. Follow [repository container guidance](../AGENTS.md#dev-servers) and [Linux development container details](../docs/internals/devcontainer.md).

## Out of Scope

- Native Pipeline definitions, step executor/lifecycle/history/UI; plan 0000004 owns these and consumes the shared Agent/Routine services.
- Knowledge catalog/index/AST/embedding state/settings, source lifecycle and retrieval implementation; plan 0000001 owns these. Routine re-ingest calls its service.
- Questions parent research protocol, question service/chat/MCP and question UI; plan 0000003 owns these and consumes Knowledge and named Agent execution.
- Historical Mongo or conversation/session/run/credential migration. New T3 state begins through normal T3 schema migration lifecycle and fresh definition loading/re-ingest.
- Kadshow/Jira generic defaults/integrations, booklet-domain shipped defaults, machine-specific endpoint defaults, arbitrary external MCP/shell engines, raw-shell Routine item types, a definition editor, generic scheduler, duplicate agent catalog/runtime, or new global worker limit. Ordinary shell/Docker work uses existing Agent tools/project scripts.
- New authorization/approval/allowlist/quota/preflight/freshness/handoff gates; retain existing T3 authorization and correctness controls.
- Generic Docker Engine abstraction, automatic target container/volume deletion, or automatic stopping of detached containers on Routine/Pipeline cancellation.
- Windows/macOS/mobile/native packaging or proof. This plan's product deployment/proof is Linux web/server/shared only.
- Replacing/renaming CodeInfo2 project-workflow `flows/`, `commands/`, `codeinfo_markdown/`, or `t3code_implement_story` with native product definitions.
