# Repository Knowledge

## Overview

Build T3's repository source, ingestion, structured AST, and embedding foundation for repository-scoped knowledge. Users configure environment-local repository sources and control their indexing lifecycle in a new Knowledge experience. T3 SQLite is authoritative for sources, ingestion runs, file-hash metadata, AST metadata, and the global embedding identity needed by T3; Chroma retains vectors, chunk documents, and retrieval metadata. Knowledge provides shared services to Codebase Questions and re-ingestion callers, without owning question orchestration or Agent execution.

This plan owns repository source configuration, ingestion and re-ingestion, structural AST indexing, embedding settings and lifecycle, Chroma-backed retrieval, and the Knowledge source UI. [Agents and Routines](0000002-agents-and-routines.md) owns Agent/Routine definitions and execution plus the shared Linux product runtime; [Codebase Questions](0000003-codebase-questions.md) owns scoped question orchestration and answer/source presentation; [Pipelines](0000004-pipelines.md) owns Pipeline definition and execution. Agree shared contracts and avoid duplicating services or UI.

Follow [repository container guidance](../AGENTS.md#dev-servers) and [Linux development container details](../docs/internals/devcontainer.md).

Reference facts: CodeInfo2 discovers Git-tracked files and falls back to a filesystem walk, filters by configured extensions and simple excluded path segments/suffixes, skips likely binary files, and does not exclude `.repos` by default. Discovery extensions do not equal AST support: the parser maps JavaScript (`js`, `jsx`), TypeScript (`ts`), TSX (`tsx`), Python (`py`), C# (`cs`), Rust (`rs`), and C++ (`cc`, `cpp`, `cxx`, `hpp`, `hxx`, `h`) to seven grammar groups. `cxx`/`hxx` are not in default discovery includes; `.c`/`.mjs`/`.cjs` discovery does not imply AST support. Chunk rows do not include exact source offsets; exact citations must come from AST ranges or current source inspection, not chunk line counts. File hashes drive added/changed/deleted/unchanged re-ingestion; no-change work avoids embeddings while corresponding vectors are intact. A different provider/model is rejected while vectors hold the global lock; the demonstrated model-change flow is remove indexed roots, unlock, choose a model, then re-ingest. CodeInfo2's LM Studio adapter claims abort support, but its pinned SDK 1.5.0 `embed` method accepts input only, so in-flight upstream abort cannot be promised. AST records are structural, not compiler resolution.

Proposed T3 design: keep stable source identity (environment plus normalized server root), run identity/status/progress/error, file-hash metadata, AST records/ranges, and active embedding identity in SQLite. Capture the stable execution configuration in memory and persist model identity, counts, status, errors, and timestamps needed by the UI; do not store historical include/exclude or endpoint snapshots without a consumer. Chroma retains vectors, chunk documents, and retrieval metadata needed for source filtering. Keep per-source override UI out of scope. Add the missing `.repos` default exclusion. A Knowledge domain service owns discovery, delta planning, embedding dispatch, AST indexing, cancellation/removal, scoped vector retrieval, and AST queries. Contracts/RPC remain thin; Questions constructs answers/citations from Knowledge results. Settings use existing environment settings and secret handling. A Knowledge page is new and must be registered in existing navigation.

## Acceptance Criteria

- [ ] **K-1 Sources and lifecycle:** A user can configure an environment-local repository source and start, observe persisted progress/status and actionable terminal errors, cancel, re-ingest, and remove its indexed content through Knowledge. Reopening/reconnecting restores persisted summaries and errors. Source files themselves are never removed.
- [ ] **K-2 Authoritative state and discovery:** SQLite is authoritative for source, run, file-hash, AST, and embedding-lock state; Chroma retains vectors, chunk documents, and retrieval metadata. Do not require SQLite chunk records or joins solely to move chunk text. Discovery retains useful CodeInfo2 Git-tracked/fallback, extension, text, and include/exclude behavior, with `.repos` excluded by default. Includes replace defaults and excludes extend defaults as in CodeInfo2; exclusions are simple segment/suffix rules, not general globs.
- [ ] **K-3 Delta and citations:** Added/changed/deleted/unchanged files produce correct chunk/vector/AST updates; unchanged re-ingestion makes no embedding calls when corresponding vectors are intact. Chunk metadata retains source/path/hash/run association but does not invent exact offsets. Citations use AST ranges or current-source inspection, not chunk line counts.
- [ ] **K-4 AST:** Structural AST records, exact one-based source ranges, and supported relationships are persisted for CodeInfo2's seven grammar groups: JavaScript (`js`, `jsx`), TypeScript (`ts`), TSX (`tsx`), Python (`py`), C# (`cs`), Rust (`rs`), and C++ (`cc`, `cpp`, `cxx`, `hpp`, `hxx`, `h`). Discovery extensions are separate: `cxx`/`hxx` are not default includes, and `.c`/`.mjs`/`.cjs` discovery does not imply parser support. Parser/query/native assets work in T3's bundled Linux server. No compiler-grade semantic claims.
- [ ] **K-5 Providers and global model:** OpenAI offers the CodeInfo2 choices (`text-embedding-3-small` and `text-embedding-3-large`, subject to configured-key availability); LM Studio uses its native SDK embedding API and available embedding-capable models. Provider discovery failures remain independent. One global provider/model/dimension space is enforced. On model mismatch, users remove indexed roots, which removes vectors and unlocks the model, select the new model, then re-ingest; no one-click global rebuild is introduced. Cancellation stops/rejects queued work and prevents later writes from cancelled work; it does not claim to abort an already in-flight LM Studio SDK request.
- [ ] **K-6 Settings and secrets:** Environment-wide include/exclude and provider/model/endpoint configuration use T3 Settings and established secret storage. Capture effective execution settings in memory; persist model identity and the counts/status/errors/timestamps consumed by the UI, without a historical configuration snapshot. No per-source filter override is required.
- [ ] **K-7 Chroma:** Chroma is a persistent sibling service in the Linux product deployment, with storage separate from CodeInfo2. Knowledge reconnects to an intact persistent index after restart. If indexed vectors are lost, normal recovery uses existing remove-indexed-content and fresh-ingestion controls, which reread source files; do not add automatic detection or a recovery API. Deliberate indexed-content removal deletes owned AST/indexed content and vectors while preserving source records and repository files. Do not create a fake zero-vector root collection or a new rebuild API/button.
- [ ] **K-8 Shared contracts and ownership:** Knowledge exposes source list/resolve, scoped vector retrieval, AST queries, start/re-ingest, cancel, remove, terminal-run wait, and persisted summary subscription through its service and typed transport contract. Questions consumes retrieval/AST results; Agents/Routines and Pipelines consume re-ingestion/terminal-run behavior. No circular dependency or duplicate catalog/service.
- [ ] **K-9 Minimal scope:** Deliver the smallest requirement-complete adaptation of CodeInfo2 behavior and existing T3 SQLite, settings, secret, service, RPC, and UI seams. No discretionary refactors/polish/unrelated repairs, duplicate catalogs/history/provider runtimes/schedulers, or new dependencies/abstractions/helpers/frameworks without an accepted requirement, verified gap, and reason reuse/minimal adaptation is insufficient. Add no new gates, approvals, receipts, preflights, freshness requirements, allowlists, quotas, global worker caps, handoff/control state, or generic Kadshow/Jira defaults. Preserve existing authorization/correctness and repository-required proof.
- [ ] **K-10 Automated proof:** Focused Vitest/@effect/vitest and SQLite.layerMemory cases cover changed behavior at its lowest useful layer, including delta/no-op, mapping under concurrent completion, cancellation late-write prevention, AST ranges/errors/cleanup, persistence/removal, and model lock/unlock. Extend fitting existing cases; no duplicated transport mirrors, type-only/static-copy checks, new harness, polling sleeps, timing deltas, retries, or per-test timeouts. Actual model-facing instruction/schema/description/result changes follow [evals/README.md](../evals/README.md) and applicable existing eval guidance; no unrelated paid evals or new harness.
- [ ] **K-11 Real-client proof:** After integration, one coordinated real-web Knowledge pass uses the existing `test-t3-app` workflow, verifies meaningful lifecycle actions and reload persistence, and captures relevant evidence. Replay can show UI only and does not prove backend embedding, provider, or deployment behavior.
- [ ] **K-12 External-provider/deployment proof:** Where real configured OpenAI and LM Studio endpoints/models/credentials exist, exercise embedding and retrieval per provider; otherwise leave that provider's proof open with the exact missing configuration. Verify Chroma restart persistence. Reuse the disposable target-project start/stop evidence owned by Agents and Routines' integrated proof; Knowledge does not require a second target-stack run. Do not claim simulated shell/files/tests as backend proof. Linux web/server/shared behavior is the target; other OS, mobile, and native packaging proof is out of scope.
- [ ] **K-13 Later required checks:** Before a later push, run `npm run container:exec -- vp run check:changed`; it is not a gate for each implementation step and is not run as part of this plan-authoring assignment.

## Out of Scope

- Repository-question orchestration, chat/MCP question entry points, answer construction, and question UI belong to [Codebase Questions](0000003-codebase-questions.md). This plan supplies source, chunk, vector, and AST retrieval data.
- File-backed Agent/Routine definitions and execution, Pipeline runtime/history/UI, Linux product server/agent runtime, project mounts and target-project Docker lifecycle belong to [Agents and Routines](0000002-agents-and-routines.md) and [Pipelines](0000004-pipelines.md). Coordinate a single Compose owner for the shared Linux product stack and Chroma service.
- No historical Mongo/session/conversation/run/credential migration. Start with fresh T3 state and re-ingest configured sources. Normal SQLite schema migrations through the existing T3 lifecycle are in scope.
- No per-source filter override UI, per-repository embedding models, automatic global model rebuild, compiler-grade semantic engine, source-editor feature, or speculative provider/dependency additions.
- No new approval or launch gates, freshness preflight, allowlist, quota, global worker cap, ownership framework, generic Docker engine abstraction, or separate infrastructure stack.
- No Windows, macOS, iOS, Android, or native packaging support/proof. Linux web/server/shared behavior is the target.
- Do not index `.repos` by default or alter the existing `flows/`, `commands/`, `codeinfo_markdown/`, or `t3code_implement_story` workflows. Native T3 definitions are separate and owned by sibling plans.
- No unrelated CodeInfo2 bug fixes or copying its Mongo/history compatibility model.
